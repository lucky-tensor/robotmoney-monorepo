<a id="test_routedeposit_balancedvault_readseachadapteronce"></a>

### test_routeDeposit_balancedVault_readsEachAdapterOnce

`_routeDeposit` into a balanced, fully-deployed vault must make
exactly ONE round of adapter reads in the allocator: pass 1
places the whole deposit and pass 2 never runs.

<i>

RED before #1391: `_targetBpsFor()` returned `10000 / 3 == 3333`, so
the three pass-1 targets summed to 9999 bps. Pass 1 could never place
the last ~1 bps of TVL, `remaining` stayed positive, and pass 2
walked all three adapters a second time — 3 reads each, not 2.

</i>

```solidity
function test_routeDeposit_balancedVault_readsEachAdapterOnce() public;
```

<a id="test_routedeposit_balancedvault_passonecompletesthefill"></a>

### test_routeDeposit_balancedVault_passOneCompletesTheFill

Pass 1 alone absorbs the entire deposit into a balanced vault: no
adapter is allocated to twice and nothing is left unrouted.

<i>

RED before #1391 — pass 2 allocated the 9999-vs-10000 shortfall,
producing a second `Allocated` for the first adapter with headroom.

</i>

```solidity
function test_routeDeposit_balancedVault_passOneCompletesTheFill() public;
```

<a id="test_routedeposit_dustdeposit_isplacedbypassone"></a>

A deposit smaller than 1 bps of TVL is the regime in which pass 1

### test_routeDeposit_devnetForkFixtureComposition_readsOnce

<a id="test_routedeposit_passtworeusespassonereadswhenpassoneplacesnothing"></a>

### test_routeDeposit_passTwoReusesPassOneReadsWhenPassOnePlacesNothing

When pass 1 allocates NOTHING and pass 2 still has to run, pass 2
reuses pass 1's reads instead of paying for a second round: only
staticcalls happened in between, so the cached values are exact
(#1391 caching remedy).

<i>

The rounding fix alone does not reach this state — it needs adapters
sitting ABOVE their effective target, which is what accrued interest
against a binding `capBps` produces. Modelled here by tight caps plus
a direct transfer into the adapters (the protocol-donation path).

</i>

```solidity
function test_routeDeposit_passTwoReusesPassOneReadsWhenPassOnePlacesNothing() public;
```

<a id="test_routedeposit_passtworereadsafterpassoneallocated"></a>

### test_routeDeposit_passTwoRereadsAfterPassOneAllocated

The cache is NOT used once pass 1 has allocated: a cached balance
